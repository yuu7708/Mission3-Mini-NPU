# Mini NPU Simulator

## 1. 프로젝트 소개

Python으로 AI의 MAC(Multiply-Accumulate) 연산 방식을 구현한 Mini NPU 시뮬레이터입니다.

입력 패턴에 두 종류의 필터(Cross, X)를 적용하고, MAC 연산 점수를 비교하여 입력 패턴을 판정합니다.

사용자 입력 모드와 JSON 데이터 분석 모드를 제공하며, 다양한 배열 크기에 대한 연산 성능도 측정합니다.

## 2. 실행 환경

- Python 3.8 이상
- Python 표준 라이브러리만 사용
- 사용 모듈: `json`, `time`, `math`, `re`
- NumPy, pandas 등 외부 라이브러리 미사용

## 3. 주요 기능

1. 사용자 입력 모드에서 3×3 필터 A와 B 입력
2. 입력한 필터 확인 및 재입력
3. 3×3 패턴 입력 및 MAC 점수 계산
4. Cross, X, UNDECIDED 판정
5. JSON 파일을 이용한 여러 크기의 패턴 자동 분석
6. JSON 데이터의 배열 크기 및 숫자 형식 검증
7. 필터 이름과 정답 라벨 정규화
8. 잘못된 데이터 및 지원하지 않는 배열 크기 검증
9. 테스트별 PASS 및 FAIL 결과 출력
10. 전체 테스트 결과와 실패 원인 출력
11. 3×3, 5×5, 13×13, 25×25 성능 측정
12. MAC 연산 평균 실행 시간 및 연산 횟수 출력

## 4. MAC 연산 방식

MAC(Multiply-Accumulate)은 같은 위치에 있는 패턴과 필터의 값을 곱한 뒤 모든 결과를 누적하는 연산입니다.

각 위치의 곱셈 결과를 `total` 변수에 더하고, 최종 합계를 연산 점수로 사용합니다.

연산은 중첩 반복문으로 직접 구현했으며, 최종 결과는 실수형(float)으로 반환합니다.

## 5. 판정 방식

Cross 필터 점수와 X 필터 점수를 비교합니다.

- Cross 점수가 더 크면 Cross
- X 점수가 더 크면 X
- 두 점수의 차이가 epsilon(1e-9)보다 작으면 UNDECIDED

동점인 경우 어느 쪽도 선택하지 않도록 처리합니다.

JSON 데이터의 정답 라벨은 다음과 같이 정규화합니다.

- `+` → `Cross`
- `x` → `X`
- `cross` → `Cross`

## 6. 데이터 검증

JSON 분석 과정에서 다음 항목을 검증합니다.

- JSON 파일의 존재 여부 및 문법
- 필터와 패턴 데이터의 구조
- 패턴 이름 형식
- 지원하는 배열 크기(5, 13, 25)
- 패턴과 필터의 행 및 열 개수
- 숫자 형식과 유효한 숫자 여부
- Cross 및 X 필터의 존재 여부
- 필터 이름의 중복 여부

잘못된 데이터가 발견되면 해당 테스트 케이스를 FAIL로 처리하고 실패 원인을 출력합니다.

사용자 입력 모드에서도 숫자가 아닌 값이나 잘못된 행의 숫자 개수를 검사하고 재입력을 요청합니다.

## 7. 테스트 결과 리포트

JSON 데이터의 총 6개 테스트 케이스를 실행했습니다.

| 테스트 케이스 | Cross 점수 | X 점수 | 판정 | 결과 |
|---|---:|---:|---|---|
| size_5_1 | 0.9 | 0.9 | UNDECIDED | FAIL |
| size_5_2 | 8.9 | 0.1 | Cross | PASS |
| size_13_1 | 0.3 | 14.7 | X | PASS |
| size_13_2 | 7.5 | 7.5 | UNDECIDED | FAIL |
| size_25_1 | 4.9 | 4.9 | UNDECIDED | FAIL |
| size_25_2 | 52.9 | 0.1 | Cross | PASS |

- 전체 테스트: 6개
- PASS: 3개
- FAIL: 3개

## 8. 실패 원인 분석

실패한 세 케이스는 프로그램 오류가 아니라 두 필터의 MAC 점수가 동일하게 나온 경우입니다.

- size_5_1: Cross 0.9, X 0.9
- size_13_2: Cross 7.5, X 7.5
- size_25_1: Cross 4.9, X 4.9

현재 판정 규칙은 두 점수의 차이가 epsilon(1e-9)보다 작으면 UNDECIDED를 반환합니다.

따라서 정답이 Cross 또는 X로 지정되어 있어도 두 점수가 같으면 정답을 확정할 수 없어 FAIL로 처리됩니다.

이 결과는 epsilon을 이용한 동점 판정이 정상적으로 동작하고 있음을 보여줍니다.

FAIL을 임의로 PASS로 변경하지 않고 실제 연산 결과와 판정 규칙을 그대로 유지했습니다.

## 10. 시간 복잡도 분석

MAC 연산은 배열의 모든 행과 열을 한 번씩 반복합니다.

N×N 배열에서는 총 N²번의 곱셈과 누적 연산이 발생합니다.

따라서 시간 복잡도는 O(N²)입니다.

배열 크기가 증가하면 연산 횟수도 제곱에 비례하여 증가합니다.

## 13. 함수 모듈화의 이유

각 기능을 독립적인 함수로 분리하여 코드의 가독성과 재사용성을 높였습니다.

예를 들어 `normalize_label()`은 JSON의 정답 라벨과 필터 이름을 동일한 규칙으로 변환합니다. 이처럼 기능을 분리하면 특정 기능만 독립적으로 테스트하거나 수정할 수 있고, 다른 기능에 미치는 영향을 줄일 수 있습니다.

## 14. 부동소수점과 EPSILON 사용 이유

Python의 실수(float)는 컴퓨터 내부에서 이진 부동소수점 방식으로 표현되므로 일부 소수 계산에서 미세한 오차가 발생할 수 있습니다.

예를 들어 `0.1 + 0.2`의 결과가 정확히 `0.3`과 일치하지 않을 수 있습니다.

따라서 두 점수를 직접 비교하는 대신 `EPSILON = 1e-9`를 사용하여 두 점수의 차이가 매우 작으면 동점으로 판단합니다.

이 기준을 통해 부동소수점 오차로 인한 잘못된 판정을 줄입니다.

## 15. 사용자 입력 모드와 JSON 모드의 동점 처리 차이

두 모드 모두 동일한 `judge()` 함수를 사용하며, 두 점수의 차이가 EPSILON보다 작으면 `UNDECIDED`를 반환합니다.

| 구분 | 사용자 입력 모드 | JSON 분석 모드 |
|---|---|---|
| 입력 데이터 | 사용자가 직접 입력 | data.json |
| 동점 판정 | UNDECIDED | UNDECIDED |
| 결과 처리 | 판정 결과를 사용자에게 표시 | expected와 비교 |
| 최종 집계 | PASS/FAIL 집계 없음 | PASS 또는 FAIL 집계 |

사용자 입력 모드는 사용자가 입력한 패턴의 판정 결과를 확인하는 것이 목적입니다.

JSON 모드는 미리 지정된 expected 값과 실제 판정 결과를 비교하므로, 동점으로 UNDECIDED가 발생하고 expected가 Cross 또는 X라면 해당 테스트는 FAIL로 집계됩니다.

## 17. 대규모 배열 처리와 최적화 방향

현재 프로그램은 3×3, 5×5, 13×13, 25×25 배열을 대상으로 성능을 측정합니다.

만약 1000×1000 배열을 처리한다면 다음과 같은 문제가 발생할 수 있습니다.

- 연산량: 1,000,000개의 곱셈 및 누적 연산
- 메모리: 백만 개의 원소를 저장하는 배열 공간 필요
- 실행 시간: Python 반복문으로 처리하면 배열 크기 증가에 따라 실행 시간이 크게 늘어날 수 있음

대규모 데이터 처리 시 다음 순서로 최적화를 고려할 수 있습니다.

1. 블록 단위 처리: 배열을 작은 영역으로 나누어 처리하여 캐시 효율을 높입니다.
2. 데이터 이동 최소화: 불필요한 배열 복사와 메모리 접근을 줄입니다.
3. 병렬 처리: 여러 연산을 동시에 처리할 수 있는 환경을 활용합니다.

최적화 적용 전후의 실행 시간을 측정하여 실제 개선 효과를 확인하는 것이 중요합니다.

## 18. CPU와 NPU의 연산 특성 및 병목 분석

CPU와 NPU는 연산을 수행하는 방식에 차이가 있습니다.

| 구분 | CPU | NPU |
|---|---|---|
| 처리 방식 | 범용적인 직렬 및 제한적 병렬 처리 | 대량의 병렬 연산에 특화 |
| 주요 장점 | 다양한 작업과 복잡한 제어 처리 | 행렬 및 MAC 연산의 높은 병렬 처리 효율 |
| 주요 병목 | 반복 연산과 메모리 접근 | 데이터 이동 및 메모리 대역폭 |

현재 Python 시뮬레이터는 중첩 반복문을 통해 MAC 연산을 순차적으로 수행합니다.

반면 실제 NPU는 다수의 연산 장치를 활용하여 여러 MAC 연산을 병렬로 처리할 수 있습니다.

대규모 배열에서는 연산 장치의 계산 속도뿐 아니라 데이터를 메모리에서 연산 장치로 전달하는 시간도 전체 성능에 영향을 줍니다.

따라서 대규모 MAC 연산의 성능을 높이려면 블록 단위 처리, 메모리 접근 최소화, 병렬 연산 구조 등을 고려해야 합니다.

본 프로젝트는 실제 NPU 하드웨어가 아닌 Python 기반 시뮬레이터이므로 CPU와 NPU의 실제 하드웨어 성능을 직접 비교한 결과는 아닙니다.

### 부동소수점 오차와 EPSILON 기준

Python의 `float`는 2진 부동소수점 방식으로 값을 저장하므로 일부 소수는 정확하게 표현되지 않을 수 있습니다.

예를 들어 다음 계산은 수학적으로 0.3이지만 컴퓨터에서는 미세한 오차가 발생할 수 있습니다.

```python
0.1 + 0.2
```

따라서 두 점수를 `==` 연산자로 직접 비교하면 예상하지 못한 판정이 발생할 수 있습니다.

이 프로젝트에서는 다음 기준을 사용합니다.

```python
EPSILON = 1e-9

if abs(score_cross - score_x) < EPSILON:
    return "UNDECIDED"
```

두 점수의 차이가 `1e-9`보다 작으면 부동소수점의 미세한 오차로 간주하여 동점으로 처리합니다.

- 점수 차이가 EPSILON 미만: `UNDECIDED`
- Cross 점수가 더 높음: `Cross`
- X 점수가 더 높음: `X`

이 기준을 통해 미세한 부동소수점 오차 때문에 잘못된 승패가 결정되는 것을 방지합니다.

### 새로운 라벨 추가 및 확장 방법

새로운 필터 라벨을 지원하려면 다음 순서로 확장합니다.

1. `normalize_label()` 함수에 새로운 라벨과 표준 라벨의 대응 규칙을 추가합니다.
2. `normalize_filter_keys()` 함수에서 새로운 라벨이 정상적으로 표준화되는지 확인합니다.
3. `data.json`에 새로운 라벨을 사용하는 테스트 데이터를 추가합니다.
4. 새로운 라벨이 기존 라벨과 동일하게 MAC 연산 및 최종 판정에 사용되는지 테스트합니다.

예를 들어 `cross`, `+`는 `Cross`로, `x`는 `X`로 통일합니다.

이러한 정규화 과정을 사용하면 입력 데이터의 표기 방식이 달라도 동일한 기준으로 처리할 수 있습니다.

### 대규모 배열 처리와 최적화 방향

현재 프로그램은 중첩 반복문을 사용하여 MAC 연산을 순차적으로 수행합니다.

배열 크기가 커질수록 연산량도 증가합니다.

- 3×3 배열: 9회 연산
- 25×25 배열: 625회 연산
- 1000×1000 배열: 1,000,000회 연산

MAC 연산의 시간 복잡도는 `O(N²)`입니다.

1000×1000 배열을 처리할 경우 연산 횟수가 크게 증가하며, 배열 데이터를 저장하기 위한 메모리 사용량도 커집니다.

대규모 배열 처리 성능을 개선하기 위한 최적화 방향은 다음과 같습니다.

1. **블록(Block) 처리:** 배열을 작은 영역으로 나누어 처리하여 캐시 효율을 높입니다.
2. **메모리 접근 최소화:** 불필요한 데이터 복사와 반복적인 메모리 접근을 줄입니다.
3. **병렬 처리:** 여러 연산을 동시에 수행할 수 있도록 작업을 분할합니다.

최적화 전후의 실행 시간을 측정하고 비교하여 실제 성능 개선 여부를 확인해야 합니다.

### CPU와 NPU의 연산 특성 및 병목 분석

**CPU와 NPU의 연산 특성**

- CPU는 다양한 종류의 작업을 처리하는 범용 프로세서이며, 순차적인 작업과 일부 병렬 작업을 수행합니다.
- NPU는 인공지능 연산에 특화된 프로세서로, 행렬 곱셈과 MAC 같은 반복적인 연산을 병렬로 처리하는 데 유리합니다.

**현재 프로그램의 연산 방식**

이 프로젝트는 Python의 중첩 반복문을 사용하여 MAC 연산을 순차적으로 수행하는 시뮬레이터입니다. 실제 NPU 하드웨어를 사용하거나 CPU와 NPU의 성능을 직접 비교하는 프로그램은 아닙니다.

**대규모 연산에서 발생할 수 있는 병목**

1. 연산량 증가: 배열 크기가 커질수록 MAC 연산 횟수가 증가합니다.
2. 메모리 접근: 연산에 필요한 데이터를 읽고 쓰는 과정에서 시간이 소요됩니다.
3. 순차 처리: 현재 구현은 반복문으로 한 번에 하나씩 연산하므로 병렬 처리의 이점을 활용하지 못합니다.

**개선 방향**

- 블록 단위 연산으로 캐시 효율 개선
- 불필요한 메모리 접근과 데이터 복사 감소
- 병렬 연산 구조 적용

이러한 개선 방향은 대규모 행렬 연산에서 연산 장치의 활용률을 높이고 병목을 줄이는 데 도움이 될 수 있습니다.
